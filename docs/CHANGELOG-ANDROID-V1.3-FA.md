# مدرسه‌یار اندروید V1.3 — تکمیل تم دخترانه و قفل اثر انگشت

## تغییرات
- اصلاح یکپارچه نمای ورود و زیرصفحه‌های آزمون‌ها، تکالیف، کارنامه، برنامه هفتگی، منابع آموزشی، یادگیری من، اعتراض‌ها، خانواده، پروفایل و صفحه تنظیمات «بیشتر».
- گروه‌بندی منوی «بیشتر» به «درس و برنامه‌ریزی»، «آزمون و ارزیابی»، «مدرسه و ارتباطات» و «حساب، همگام‌سازی و امنیت».
- نگهداری همه عناصر واقعی و کنترل‌های پنل وب؛ جابه‌جایی دکمه‌های منوی اصلی بدون تغییر handler و بدون انتقال اطلاعات آموزشی به سرور جدید.
- استایل هماهنگ برای پنجره‌های اعلان، گفت‌وگوی معلم، فرم‌ها، ورودی‌ها، اسناد درسی و آزمون‌های تستی/تشریحی.
- قابلیت **اختیاری** قفل بیومتریک اندروید با BiometricPrompt، فعال‌سازی از صفحه «بیشتر» پس از ورود عادی موفق، احراز هویت برای فعال/غیرفعال‌سازی، و پوشاندن محتوای پنل در بازگشت از پس‌زمینه.
- احراز هویت بیومتریک هرگز جای توکن معتبر سرور یا ورود اولیه با رمز مدرسه را نمی‌گیرد.
- آیکون کتاب باز منتخب، داشبورد دخترانه V1.2، پیام‌رسان، سرویس نوتیفیکیشن و کدهای سرور بدون تغییر مانده‌اند.

## نصب و استفاده
1. از پرونده‌های قبلی و پیش‌نویس‌های محلی بکاپ منطقی تهیه کنید؛ ترجیحاً ابتدا اپ فعلی را حذف نکنید.
2. ZIP کامل را در مخزن خصوصی GitHub استخراج/آپلود کنید؛ یا محتوای ZIP پچ را در همان مسیرهای مخزن جایگزین کنید.
3. از Actions گزینه Build Android APK را اجرا و APK را دریافت کنید. Gradle/AndroidX برای BiometricPrompt هنگام ساخت دانلود می‌شوند.
4. برنامه را روی گوشی دارای اثر انگشتِ ثبت‌شده نصب کنید. نخست با حساب معمولی مدرسه وارد شوید.
5. از پایین «بیشتر» → «حساب، همگام‌سازی و امنیت» → «فعال‌سازی ورود با اثر انگشت» را بزنید و احراز هویت اندروید را تأیید کنید.
6. اپ را به پس‌زمینه بفرستید و برگردید: صفحه قفل باید نمایش داده شود. با اثر انگشت/اعتبار دستگاه (اندروید ۱۱ به بعد در صورت پشتیبانی) باز کنید.
7. برای خاموش کردن: در «بیشتر»، «غیرفعال‌کردن قفل اثر انگشت» را بزنید و دوباره بیومتریک را تأیید کنید.

## نکات امنیت و محدودیت‌ها
- فعال‌سازی بیومتریک **نیازمند رضایت صریح** است. بدون ثبت بیومتریک سیستم‌عامل فعال نمی‌شود.
- برای API 26–29، BiometricPrompt به بیومتریک قوی ثبت‌شده نیاز دارد. روی اندروید ۳۰ به بالا گزینه قفل امن دستگاه نیز ممکن است از سوی سیستم‌عامل نمایش داده شود.
- بعد از اتمام/انقضای نشست سرور باید مانند گذشته دوباره وارد حساب مدرسه شوید؛ تأیید اثر انگشت نشست منقضی را زنده نمی‌کند.
- این قفل به‌معنی رمزگذاری کامل اطلاعات IndexedDB نیست؛ مکانیزم وب موجود برای کش همچنان برقرار است. گوشی مشترک نیازمند سیاست خروج/پاک‌سازی امن جداگانه است.
- زیرصفحه‌ها در V1.3 استایل یکسان دارند، اما **منطق و قالب اصلی وب** آن‌ها حفظ شده؛ بازنویسی کامل اختصاصی هر ۲۸ ماژول به Native انجام نشده است.
- **Push واقعی** هنوز تا زمان پیکربندی Firebase و تطبیق افزونه سرور فعال نمی‌شود.
- آزمون‌های Node و بررسی نحوی JS موفق‌اند، اما ساخت نهایی APK و تست بیومتریک روی گوشی در این محیط انجام نشده است.
- اگر GitHub Actions برای هر اجرا Debug keystore جدید بسازد، APK ممکن است روی نصب قبلی به‌روزرسانی نشود. پیش از حذف نسخه قبلی، پیش‌نویس‌ها و موارد در صف ارسال را بررسی کنید؛ نصب تازه ممکن است داده آفلاین را پاک کند. برای نسخه تولیدی باید کلید امضای ثابت تعریف شود.
